What release 2611 changes for ABAP developers: CDS indexes and RFC error details

The source post is a roundup with one-line items, so what follows is limited to what it states. The CDS DDL statement Define Index now creates unique, text and standard indexes directly on CDS table entities. Previously secondary indexes were handled in a separate dictionary step. Verify the exact syntax on the linked detail page before using it in class.

For RFC calls using a communication target, error details are now available through Get_Details on the exception object and Get_Last_Error on the session object. The split suggests one path for exception-based handling and one for session-level state. The post does not explain the exact differences, so test both against a failing destination.

In ADT for Eclipse, authorization default variants (R3TR SUCO) can now be created and maintained. ADT for VS Code gains Service Consumption Model, Swagger for OData services, Transport Organizer, SQL Notebook, ATC exemptions and an ABAP Dictionary log. An ADT MCP Server is offered for both IDEs.

This is the ABAP environment release (BTP), not on-premise S/4HANA 2023. Do not tell trainees these features exist on their on-premise systems without checking.

Dynamic paper size in a DDIC-based Adobe Form

The goal is one form printing on A4 or Letter without duplicates. Build two page sets, A4 and LETTER. Each has master pages Page1 (pagination Max = 1) and Page2 (no restriction). Page2 NEXT acts as the boundary between sets.

Place a small flowed subform PaperSize on the master Page1 of each set, bound to the paper-size value. A JavaScript script hides the one that does not match, so only the correct Page1 is used. Its pagination is set to Page1_A4 or Page1_Letter. The author mentions an optional hidden subform mapping the value to text for scripts, since the data node can be read directly.

The content subform BODY must use Follow Previous and Continue Filling Parent so pagination follows the selected Page1. The sizes must share compatible content-area widths, otherwise content is misaligned or truncated. The author centred the content area for Letter. With more than two master pages, order them in print sequence and set a max count on each non-NEXT page.

The author says Output Management's master/content layout split is preferred where available. The JavaScript and screenshots are not in the excerpt.

  • Page sets and master pages
  • Pagination Max restriction
  • Follow Previous / Continue Filling Parent
  • Hidden PaperSize subform
  • NACE DDIC-based forms

Migrating PO REST receiver error handling to iFlows

PO's REST receiver adapter could evaluate several sources: Exception, HTTP Status Code, HTTP Status Text, HTTP Header Element, Text Content, JSON Expression, XPath Expression and Always. Integration Suite has no adapter-level equivalent, so each rule becomes iFlow logic.

For the Direct Response pattern with 'Always', disable Throw Exception On Failure on the receiver adapter. Otherwise the configured response is never returned. For 'Exception', keep it enabled so receiver errors reach the Exception Subprocess. The subprocess must end with an End Event. An Error End Event returns the default error response with MPL ID.

A handled exception shows Completed in the MPL instead of Failed, which affects monitoring. HTTP Metadata Validation uses a regex on ${header.CamelHttpResponseText} routed through a Router.

Caution: the post's example tests 'Not Found' with a space while the PO value is 'NotFound', and an unescaped . matches any character. Check which string the real reason phrase matches. The text is cut off, so later patterns are unseen.

  • Throw Exception On Failure
  • Exception Subprocess
  • End Event vs Error End Event
  • MPL status
  • Router regex on CamelHttpResponseText

Interview questions

Grounded in today's material. Open each one to see a model answer.

Mid-level Your CAP app works locally on SQLite but crashes on Cloud Foundry with 'Cannot find @sap/xssec'. How do you diagnose and fix it, and what is wrong with switching auth to dummy?

In production CAP resolves auth to jwt, which requires @sap/xssec at runtime. A missing dependency crashes at startup, so first add the package to dependencies and bind an XSUAA service instance in the MTA. Use cds env requires.auth --profile production to confirm the resolved config. Setting auth kind to dummy removes authentication entirely, so anyone can call the service. That is acceptable only in a trial, not in a real project. Also check that the HANA profile is set for production and that the MTA build uses cds build --production.

Blog: SQLite to SAP HANA Cloud with CAP Profiles: A Beginner's Wal
Senior You migrate a PO REST receiver channel with error handling 'Exception' to Integration Suite. What must be configured so the custom error response is returned, and how will monitoring look?

Keep Throw Exception On Failure enabled on the receiver REST adapter, so receiver failures raise an exception that reaches the Exception Subprocess. Build the custom response there with a Content Modifier or Groovy script. End the subprocess with a normal End Event. An Error End Event returns the default error response with the MPL ID instead of your custom one. Because the exception is handled, the MPL status shows Completed, not Failed, so monitoring and alerting based on status must be adjusted. For the 'Always' rule you would instead disable Throw Exception On Failure, otherwise the configured response is never returned.

Blog: Migrating REST Error Handling from SAP Process Orchestration
Architect A client needs Datasphere data with joins and aggregates exposed to an external tool via OData. What is your design?

The documented Datasphere OData API supports $select, $filter, $orderby, $top, $skip, $count, $batch and input parameters, one asset per service URL. It does not document joins, GROUP BY/HAVING, subqueries, CTEs, UNION or date functions. So the join and aggregation logic belongs in a Datasphere view (relational or analytical model), which is then exposed with simple filters. That also keeps logic centralised and pushed down to the database. For other access paths such as SQL access, check SAP's current documentation. I would also confirm whether limits are planned to change, since the thread has no roadmap statement. Compared with S/4HANA Gateway, which offers $expand and $apply, the design must move logic into the model.
