Designing a testable HTTP client in ABAP Cloud (Azure SDK pattern)

The Azure SDK separates concerns into layers. A typed service client such as ZCL_AZ_BLOB_CLIENT builds requests. A policy pipeline handles retry, auth and logging. A credentials interface supplies tokens, and a transport sends the request. Every client accepts an optional transport, so a unit test can pass a double instead of calling if_web_http_client.

The tests are declared RISK LEVEL HARMLESS DURATION SHORT, so they run offline in ATC and ADT. Integration tests skip themselves when no connection is configured. Credentials implement one interface: client secret, managed identity, an environment credential reading a table, and a default credential that chains them. A token cache avoids repeated token calls.

For Blob access the post recommends a User Delegation SAS signed by an Entra ID identity, so no account key is stored. For your own code, put the HTTP call behind an interface, inject it through the constructor, and write test doubles that return canned responses. The post is cut off and the samples are illustrative, so check the repository before teaching from it.

  • Injectable transport / test double
  • RISK LEVEL HARMLESS unit tests
  • Credential interface and token cache
  • User Delegation SAS vs Shared Key
  • Released APIs only for ABAP Cloud

Joining VBPA to the right SD header safely

VBPA is keyed by client, document number, item number and partner function. Header-level partner rows normally use item 000000. The document number does not say whether the row belongs to a sales document, delivery or billing document, and number ranges can overlap across VBAK, LIKP and VBRK. [97] asks how to find the header.

A three-way inner join on VBELN is risky: it can match a VBPA row to the wrong header or drop rows. The safe pattern is to determine the document category first, for example from the document flow, and then join each header separately, combining the results with UNION. Each branch joins VBPA to exactly one header table and filters on that document type.

A sketch in Open SQL: SELECT p~vbeln, p~parvw, h~erdat FROM vbpa AS p INNER JOIN vbak AS h ON h~vbeln = p~vbeln WHERE p~posnr = '000000' and the same for likp and vbrk, combined with UNION. Verify key fields and any S/4HANA changes on your release before using it. Note that a UNION still depends on number ranges not overlapping for the same VBELN, so confirm that in the target system.

  • Document category
  • UNION of per-header joins

Interview questions

Grounded in today's material. Open each one to see a model answer.

Senior How would you design an HTTP client class in ABAP Cloud so it can be unit tested without a network call?

Define an interface for the transport that sends a request and returns a response, and have the client class depend on that interface. In production, the implementation wraps if_web_http_client created from a destination. The constructor or a factory accepts an optional transport so tests can inject a test double returning canned responses. Keep auth, retry and logging as separate policies around the transport. Authentication should come from a credentials interface with a token cache. Mark the tests RISK LEVEL HARMLESS and DURATION SHORT so they can run in ATC and ADT, and keep any real integration tests skipping themselves when no connection exists. Only use released APIs so the code activates in ABAP Cloud.

Mid-level An external client gets 'CSRF token is invalid' on an OData V4 POST although it sends the fetched x-csrf-token. How do you debug it?

First reproduce it with a plain HTTP client. Send a GET with x-csrf-token: Fetch and note both the token header and any Set-Cookie headers in the response. Then send the POST with the token and the cookies, and again with the token only. If the second fails with /IWBEP/CM_V4H_RUN/042, the token is tied to a session cookie the client dropped. The usual fix is to enable a cookie jar or forward the cookies from the fetch response on the POST. The reporting post says the check depends on a cookie most clients do not return, but the cookie name was not in the supplied text, so confirm it in your system's traces. Also check that the fetch and the POST go to the same host and session.

Blog: "CSRF token is invalid" with a valid token: five things I le
Architect You are asked to retrofit changes from non-upgraded QA into an upgraded DEV system during an SPS upgrade. What are the risks of uploading whole program sources?

Whole-source upload copies everything in the file, not only the customer change. For a Z object that is acceptable if no one has changed it in DEV since. For an SAP-delivered object that the upgrade modified, it can restore old SAP code and undo corrections. It also bypasses the transport system, so there is no audit trail and no clean import path to later systems. SPAU and SPDD exist for adjusting modified SAP objects during the upgrade, and file uploads sidestep them. The better approach is to check object ownership, use transports or version comparison for Z objects, handle modified SAP objects through the adjustment process, and review the differences before activation.

VBPA join trap

*Do not join VBPA to VBAK, LIKP and VBRK on VBELN alone.*

VBPA is keyed by VBELN, POSNR and PARVW. VBELN does not tell you which header table the row belongs to.

Safer:
- one join per header table
- filter POSNR = '000000' for header partners
- combine with UNION
- check number ranges on your system

Silent wrong rows are worse than errors.
