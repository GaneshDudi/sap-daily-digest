Deep dives

The most valuable technical posts, explained.

Application Job as a batch alternative to calling a Fiori app's backend

Ref 55 asks how to run the standard F0712 Manage Supplier Line Items app on a schedule with a saved variant and mail the result. The item does not give a solution. Below is a general pattern for this kind of requirement.

A Fiori app is a UI on an OData service. That service is backed by CDS views, and in the RAP case by a service binding. You can find the service and CDS view through the app's details in the Fiori launchpad or the app library. In ADT you can then open the service binding and the CDS view. A batch job does not need to call OData. The class can read the underlying released CDS view directly with ABAP SQL.

An Application Job class implements IF_APJ_DT_EXEC_OBJECT, which defines the parameters shown in the job template, and IF_APJ_RT_EXEC_OBJECT, which holds the execution logic. Job parameters become the filter inputs, typically select-options. Saved UI variants are stored by the Fiori framework. The item does not show a supported API for reading them from ABAP, so I would not rely on that. Store the filter values explicitly in the job template instead.

Do not call the OData service from the job to reuse the app's logic. Use the released CDS view, check authorization behaviour, and send mail through the supported mail API. This keeps the pattern reusable across several reports.

  • `IF_APJ_DT_EXEC_OBJECT` / `IF_APJ_RT_EXEC_OBJECT`
  • Job catalog entry and job template
  • Finding the CDS view behind a Fiori app
  • Reading released CDS views with ABAP SQL
  • Explicit filter parameters instead of UI variants

Debugging @Semantics.largeObject on a generated RAP object

Ref 25 reports that the upload control does not show in the Fiori Elements preview, although the annotations are on the R-view. They use @Semantics.mimeType: true, and @Semantics.largeObject with mimeType, fileName, acceptableMimeTypes and contentDispositionPreference: #ATTACHMENT. The item does not give a resolution.

Check these points in order. The annotations must be on the element that holds the binary content (an abap.rawstring or abap.lchr-style field). mimeType and fileName must reference actual elements of the same view. Then check where the annotations must be effective. In a RAP stack the projection view exposes the field, so the annotations and the field need to be visible in the projection as well. The preview reads the metadata of the published service, so an outdated service means an outdated UI. Re-publish the service binding and clear the metadata cache.

The upload control also needs the behaviour to permit the field to be updated, and the field must not be read-only. Those two checks are typical causes when annotations look correct but nothing renders. I state them as things to verify, not as a confirmed cause for this post.

  • `@Semantics.largeObject`
  • `@Semantics.mimeType`
  • Projection view exposure of annotated fields
  • Service binding re-publish and metadata cache
  • Field control in behaviour definition

Global HEX enablement: a staged validation method

Ref 40 describes a 6-step method to enable the HANA Execution Engine (HEX) globally on large S/4HANA systems after earlier regressions. HEX uses JIT compilation and operator fusion. The article states that no formal SAP compatibility matrix exists and that testing is the only reliable verification. It also states that HANA 2.0 SPS08+ resolved major known issues from earlier versions.

The article sorts legacy query hints into four groups: ignored by HEX, blocks HEX execution, shapes the HEX plan, and independent of engine. This matters for ABAP developers who use %_HINTS or AMDP with hints. A hint that blocks HEX silently keeps the query on the old path. Legacy-interface queries in SQL Mode can benefit from HEX once OLAP-forcing hints are removed.

Practical takeaway: establish a baseline of runtimes for your top SQL statements, enable HEX in a controlled scope with a rollback path, compare, and use plan cache and engine rejection diagnostics to see why a statement falls back.

  • HEX JIT and operator fusion
  • Hint categories
  • SQL Mode for legacy interfaces
  • Baseline and rollback
  • Plan cache engine rejection diagnostics

Interview questions

Grounded in today's material. Open each one to see a model answer.

Mid-level A RAP business object has @Semantics.largeObject and @Semantics.mimeType annotations, but the Fiori Elements preview shows no upload control. How do you investigate?

First confirm the annotations sit on the binary content element and that mimeType and fileName reference real elements in the same view. Check that the projection view exposes these fields and that annotations are effective at that layer. Then re-publish the service binding and reload the metadata, since the preview reads the published service. Next, check the behaviour definition so the field is not read-only and can be updated. Finally, inspect the $metadata document in the browser to see whether the annotations reach the OData layer at all. If they are in $metadata but the UI does not react, the problem is in the Fiori Elements layer rather than the CDS.

Senior How would you run the logic of a standard Fiori report on a schedule with fixed filters and email the output?

Identify the OData service and CDS view behind the app through the app details and ADT. Build an Application Job: a job catalog entry, a job template and an ABAP class implementing IF_APJ_DT_EXEC_OBJECT and IF_APJ_RT_EXEC_OBJECT. Expose the filters as job parameters and convert them to range tables. Read the data with ABAP SQL on the released CDS view, not by calling the OData service. Do not depend on saved UI variants, because a supported API for reading them is not established. Send the result through the supported mail API and write to the application log. This gives a reusable template across reports.

Architect How would you plan a global enablement of the HANA Execution Engine on a large production S/4HANA system?

Treat it as a staged change with a baseline and rollback. Record runtimes of the most important statements and workloads first. Check the HANA revision, since SPS08+ resolved major known issues from earlier versions, and no official compatibility matrix exists. Review query hints, because they fall into four groups: ignored, blocking HEX, shaping the plan, or engine independent. Remove OLAP-forcing hints for legacy-interface queries in SQL Mode if you want them to benefit. Enable in a controlled scope, compare plans and runtimes, and use plan cache and engine rejection diagnostics to find fallbacks. Roll back if regressions appear, and only then extend the scope.
