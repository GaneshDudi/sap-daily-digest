Fine-tuning a local model for agentic ABAP: measured results and negative findings

The author continued-pretrained Qwen3.6-35B-A3B (6-bit MLX) on raw ABAP source and docs, then ran it as an agent through a self-built Eclipse MCP server with about 20 tools. The test was 11 tasks run 3 times each. The mean went from 30.9 to 53.8 (round 1), 59.4 (round 2) and 72.9 after 8 prompt rules. More same-type code and about 1,300 repair examples did not help. The model corrected only about 37% of failed tool calls in later turns. In the pilot, the local implementer took 23 minutes and had 2 units sent back. The small cloud implementer took 3.8 minutes with 0 sent back. Both passed all tests.

Why it matters: After round 1, the author found the lost points came from agent behaviour, not ABAP knowledge. Prompt rules were a cheaper lever than more data. With 33 runs per measurement, differences under about 6 points are noise. Caveats: the rules were written after seeing the test failures, the pilot is a single run, and the post is cut off and inconsistent on hardware.

Reading an ADT communication log failure: the ST_FB_ADT_FUNC case

ADT does not read a function module the way SE37 does. The editor requests a resource such as GET /sap/bc/adt/functions/groups/swea/fmodules/swe_event_create. The backend serializes the FM metadata to XML through a simple transformation, here ST_FB_ADT_FUNC. If serialization fails, the client reports 'content can not be synchronized' [2].

The communication log shows the real cause. The response carries ExceptionInvalidData in the com.sap.adt namespace, and the original exception is CX_SY_CONVERSION_NO_DATE_TIME. A value that is not a valid date in XML format reached the transformation. This points at the backend data, not at Eclipse [2].

The post has no answer, so the fix is unknown. General troubleshooting, not confirmed by the post: display the FM in SE37 to see whether it is ADT-specific, search SAP Notes for the transformation name and FM, and check ST22 for the dump of the original exception. Compare with another FM in the same group to see whether the problem is isolated.

  • ADT resource URIs for function modules
  • Simple transformation ST_FB_ADT_FUNC
  • CX_SY_CONVERSION_NO_DATE_TIME
  • ExceptionInvalidData in the communication log
  • Separating backend data errors from client errors

Clean-core options when no released API exists (VB11/VB01, ANLC/ANLZ)

Two posts hit the same wall. For VB11/VB01 condition records from CPI, the poster found no released API on api.sap.com for private cloud [10]. For ANLC/ANLZ, they found no extraction-enabled views [23]. Both need the same first step: filter the released-API catalogue by the exact edition and release, and check the released CDS views and APIs.

If nothing is released, the options are a classic BAPI or function module, a custom wrapper, or a custom CDS view. A custom ABAP CDS view for extraction would use @Analytics.dataExtraction.enabled: true. That is a possible approach, not in the post, and subject to release and clean-core rules [23]. A wrapper should be documented as a deliberate deviation from the clean-core policy.

For ANLC, the claim that the values are not in ACDOCA is the poster's own and unverified. Before designing, reconcile candidate sources against FI-AA reports. FAAT_PLAN_VALUES and FAAT_DOC_IT are the alternatives the poster names [23]. Also confirm which transaction maps to determination and which to exclusion in VB11/VB01 before building anything [10].

Evaluating an AI agent for ABAP: noise, ablation and test overfitting

The fine-tuning post gives a usable method. It ran 11 ABAP tasks, 3 runs each, and measured noise of about 6 points. So round 2's gain (53.8 to 59.4) is inside the noise, and only the jump to 72.9 after prompt rules is clearly larger [4].

Scoring was strict. An object left inactive, or a forbidden object changed, scores 0, and hidden unit tests give the rest. The author's diagnosis was that the lost points were agent behaviour: what to do after an error, which objects to touch, when to stop and ask. The 8 rules include 'change only the objects the task names' and 'if a business rule is missing, stop and ask' [4].

Caveats matter. The rules were written after seeing failures on the same tasks, so gains on new tasks may be smaller. The pilot is one run on one design document. Adding same-type code and about 1,300 repair examples did not help; 'Field X is unknown' stayed at 16% corrected. One concrete ADT-relevant finding: the base model wrote function module parameters as an SE37-style comment block, which ADT rejects. The trained model writes them in the FUNCTION statement [4].

  • Run-to-run noise
  • Ablation across rounds
  • Behavioural rules vs training data
  • Overfitting to the test set
