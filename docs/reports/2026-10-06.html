Deep dives

The most valuable technical posts, explained.

RAP change documents: behavior definition plus custom entity history

The standard route avoids a hand-built audit table. First create a Change Document Object in ADT. Then enable the Change Document Logging flag on every data element whose field you want tracked. This is the step most likely to be missed, and without it nothing is written.

In the behavior definition, the changedocuments directive names the object and the logging mode per operation. The post uses create: key, update: data, delete: none, so RAP writes the change documents as part of the save sequence.

To display history, define a RAP custom entity annotated with @ObjectModel.query.implementedBy: 'ABAP:...'. The class implements if_rap_query_provider~select. It converts the request filter with io_request->get_filter()->get_as_ranges(), calls cl_chdo_read_tools=>changedocument_read(), and maps the result fields: changenr, tabkey, fname, value_shstr_old, value_shstr_new, chngind, udate, utime and username. Because the provider builds the result in ABAP, you must also handle paging and sorting yourself if the UI sends them.

  • Change Document Object
  • Data element logging flag
  • RAP custom entity
  • if_rap_query_provider
  • get_as_ranges

Template-driven HTML email with CL_SMTG_EMAIL_API and CL_BCS

The design separates content from logic. Subject and body are stored as Email Templates in S/4HANA, and ABAP only supplies data and sends. CL_SMTG_EMAIL_API handles the template side, with CL_BCS as the underlying send infrastructure.

Inline images use CID references (RFC 2392 Content-ID). The HTML refers to the image as cid:... and the image part is attached with a matching Content-ID. This lets signatures and logos render in the body instead of appearing as separate attachments.

The trade-off to teach is template governance versus code control. Content changes then follow the template maintenance process rather than a code transport.

Dependent F4 help: why BSIS and SKA1 both fail the BUKRS requirement

The question tries two table-based search help references. BSIS-HKONT is a large line-item table, so the F4 is slow. SKA1-SAKNR is chart-of-accounts level and has no BUKRS, so it cannot filter by company code [47].

The material gives no accepted answer, so what follows is a general approach. The account-to-company-code assignment sits in SKB1, which carries both BUKRS and SAKNR. A search help or value help based on SKB1 can use BUKRS as an input parameter, and a search help exit can read the screen value of BUKRS. This is a design suggestion, not something stated in the source.

The lesson is to pick the table that holds the filter key and to avoid line-item tables for master-data lookups.

Senior How would you implement change history for a RAP business object without a custom audit table, and how would you display it?

Use the standard Change Document framework. Create a Change Document Object in ADT and enable the Change Document Logging flag on each data element you want tracked. Without that flag nothing is logged. Then add the changedocuments directive to the behavior definition, specifying logging per operation, for example create: key, update: data, delete: none. To display history, build a RAP custom entity with @ObjectModel.query.implementedBy. The query class implements if_rap_query_provider~select, converts the filter with get_as_ranges(), and reads the data with cl_chdo_read_tools=>changedocument_read(). It maps the fields (changenr, tabkey, fname, old and new values, chngind, date, time, user) to the entity. Paging and sorting have to be handled in the provider.

Blog: Implementing Change Logs in RAP on SAP BTP ABAP Environment
Mid-level Why use email templates with CL_SMTG_EMAIL_API instead of building HTML in ABAP, and how do inline images work?

Templates keep subject and body outside the code, so branding or wording changes do not need a code transport and can follow template governance. ABAP supplies only the data and triggers the send. CL_SMTG_EMAIL_API works with the templates, and CL_BCS provides the underlying send infrastructure. For inline images, the HTML references the image with a cid: Content-ID (RFC 2392). The image is added as a related part with the same Content-ID, so it renders in the body instead of appearing as an attachment. The trade-off is that you lose some programmatic control over the HTML structure.

Blog: Sending Branded HTML Emails in SAP S/4HANA Using Email Templ
Senior A BADI implementation for a standard Fiori app extension never triggers. How do you diagnose it?

First confirm you chose the right enhancement spot, because similar BADIs exist, as in the My Inbox case with /IWWRK/ES_TGW_CUSTOM_ATTRIBUTE and /IWPGW/BADI_TGW_TASK_DATA [21]. Check that the implementation is active, any filter values match, and the BADI is called for your scenario. Set a breakpoint in the BADI call point or in CL_EXITHANDLER. Then verify the app-side configuration, such as the catalog tile parameter showAdditionalAttributes, so the request actually reaches that code path. If the app is task-type specific, check that your task is registered for that scenario. Finally, check the gateway service and trace the backend call to see which BADI is hit.
