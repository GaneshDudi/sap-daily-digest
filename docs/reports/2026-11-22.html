MDF OData upsert: warningAcknowledged lets API calls pass business-rule warnings

Business-rule warnings on custom MDF objects make OData v2 upserts fail by default, while the UI succeeds after the user clicks OK. Adding ?warningAcknowledged=true to the /odata/v2/upsert URL skips the warnings. Users with the Admin access to MDF OData API permission bypass warnings automatically. The failure response shows httpCode 500 with the warning text and an instruction to set the flag.

Why it matters: Testing under an admin integration user hides the failure that non-admin production users will hit. The author also advises validating the data the warning protects before using the flag.

qRFC queue sequencing: why a stuck GI blocks the reversal

In the case described, EWM sends Goods Issue confirmation to ERP via qRFC, and the reversal is queued separately on a later day. If the GI queue entry is stuck in ERP, the reversal fails with 'Cancellation Date Is Before the Goods Issue Date'. Entries in one queue are processed in order, so a failed first entry blocks later ones.

The post's workaround is to open the failing entry with Debug Queue in the qRFC monitor (SMQ1 for outbound, SMQ2 for inbound). The author then edits TIMESTAMP_UTC in the table HEADER_DEADLINES[] inside BAPI_OUTB_DELIVERY_CHANGE and continues with F8.

This is a data change made in a debugger. It needs authorisation, approval and a document-history check, and the author says it is not a standard solution. The post does not say how to stop the queue getting stuck, so root-cause analysis of the GI failure is left open.

For teaching, the useful point is that the order of LUWs within a queue is a functional dependency. Diagnose the first failing entry, not the last one.

Clean-core decision order for a Public Cloud allocation requirement

The discussion post names four options for automating a monthly cost allocation. Allocation drivers (hours per project) come from another system and are currently handled in Excel, costing two days per close.

The order of preference: first, upload drivers as statistical key figures and use standard allocation. Second, key-user extensibility (custom fields, custom logic, custom reports). Third, a side-by-side extension using released APIs, in-system or on SAP BTP. Fourth, simplify the allocation key with the business so nothing is built.

The post names no specific apps or APIs. Before approving an extension, check upgrade impact, cost, ownership and audit trail. The post says 'half-yearly' upgrades; verify the cadence against current SAP documentation.

The point for ABAP developers is that in Public Cloud the question is which extensibility tier fits, not how to code it.

Mid-level An OData upsert on a custom MDF object succeeds in the UI but fails for the integration user. What do you check?

First check whether a business rule on the MDF object raises a warning. In the UI the user acknowledges it with OK, but the API call fails by default because warningAcknowledged is false. The error message echoes the warning text and says to set the flag. Adding ?warningAcknowledged=true to the upsert URL skips the warning. Check the permissions as well: users with Admin access to MDF OData API skip warnings automatically, so tests under an admin user will not show the failure. Before using the flag, validate the data the warning was meant to protect, and consider whether the rule should be an error instead.

Senior A qRFC queue between EWM and ERP fails with 'Cancellation Date Is Before the Goods Issue Date'. How do you analyse it?

Start from the sequential nature of qRFC: entries in a queue are processed in order, so a failed entry blocks later ones. Here a GI queue is stuck in ERP and a reversal was queued on a later day. Look in SMQ1 or SMQ2 for the first failing entry and find why the GI failed. The post shows a workaround: Debug Queue, and change TIMESTAMP_UTC in HEADER_DEADLINES[] in BAPI_OUTB_DELIVERY_CHANGE. That edits business data in a debugger, so it needs approval and a document-history check, and it is not a standard fix. I would prefer fixing the GI failure and reprocessing in order.
