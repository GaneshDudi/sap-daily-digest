Range copy vs FOR projection: what ends up in the table

A select-option s_bukrs is a range table with sign, option, low, high. If the target gt_bukrs has the same range line type, gt_bukrs = s_bukrs. copies every row with all four components. That is the shortest and correct way to duplicate a range.

A VALUE #( FOR ls IN s_bukrs ( ls-low ) ) expression builds a table whose line type is whatever the target has. For a plain table of bukrs it keeps only low and drops sign and option. So an exclude row or a pattern option would silently become a plain value. The two forms are therefore not interchangeable; the choice depends on the target type.

Projection becomes useful when you need to filter or transform, for example FOR ls IN s_bukrs WHERE ( sign = 'I' AND option = 'EQ' ) ( ls-low ). The thread's snippets also had errors: looping over a field symbol that was never assigned a table does not compile. Remember that LOOP AT ... INTO DATA(...) needs 7.40 SP08 or later.

  • VALUE # with FOR
  • Table assignment semantics
  • FOR ... WHERE filtering

Mid-level A colleague replaces gt_bukrs = s_bukrs with a VALUE #( FOR ... ( ls-low ) ) expression. What changes?

The direct assignment copies every row of the range table including sign, option, low and high, provided the target has the same line type. The FOR expression with ( ls-low ) builds rows from the LOW component only. If the target is a plain table of BUKRS, sign and option are lost, so exclusions and patterns become simple values. That can change selection results silently. FOR is the right tool when you need to filter, for example WHERE ( sign = 'I' ), or to project a component. For a plain duplicate of a range, use the direct assignment.

Range copy vs FOR

*Quick ABAP check:* are these the same?

`gt_bukrs = s_bukrs.`
`gt_bukrs = VALUE #( FOR ls IN s_bukrs ( ls-low ) ).`

No.

The first copies *sign, option, low, high* (if types match).
The second keeps only *LOW* and drops sign/option, so an exclude row becomes a plain value.

Use FOR when you filter or project, e.g. `WHERE ( sign = 'I' )`.
