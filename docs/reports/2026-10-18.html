Reading release states and what 'no entry' means in ABAP Cloud

The BAPI count shows 19 released, 148 'not to be released' and 5,320 with no release entry among 5,487 function modules. In ABAP Cloud (language version 'ABAP for Cloud Development'), only objects with a C1 release contract for cloud use can be referenced. An object with no entry has no such contract, so it is not available.

In ADT, you can see an object's API state in the Properties view, on the API State tab. It shows the contracts, such as C0 for extensibility and C1 for system-internal use, and the release state of each. Also check whether SAP names a successor object. For a 'not to be released' object, the successor is usually a released CDS view, a RAP business object, or a released class.

The post does not say how the counts were read. A common way to read this data is through the release-state information in the system, but that is an assumption, not something the post states. Use the figures as a lab snapshot and verify in your own system.

Debugging header information in nested RAP projections

The Fiori Elements object page header comes from @UI.headerInfo on the projection view of each entity. It has typeName, typeNamePlural, title.value and description.value. If these point to fields combined with separators, an empty child value leaves a trailing '/'. That matches '8001 /' and '8001 / /', although the post does not show the code.

Check these, entity by entity. First, which field each title and description references. Second, whether that field is populated on the child rows, or only on the root. Third, whether the parent association is exposed in the projection (_Customer with redirected to parent) and the composition is declared with redirected to composition child in the parent projection.

If you want parent values on a child page, add them to the child view through the parent association, for example _Customer.CustomerNumber. Do not rely on navigation context to supply them. This is a debugging approach, not a confirmed diagnosis for this case.

Senior A colleague wants to call a BAPI from a class written in ABAP Cloud development. How do you decide whether that is allowed?

ABAP Cloud only allows use of objects that have a release contract for cloud use (C1). I would open the BAPI in ADT and look at the API State in its properties. If it has no release entry, it is not released for ABAP Cloud, even though it works on-premise. The same is true if it is marked 'not to be released'. Only a small share of BAPIs are released: one lab count found 19 of 5,487. If it is not released, I would look for a released successor such as a released CDS view or RAP business object. If none exists, a wrapper in a classic-language-version class may be an option, called through a released interface. That keeps the cloud-ready code clean.

Mid-level What does 'no release entry' mean for an object, and how does it differ from 'not to be released'?

'Not to be released' is an explicit statement that SAP does not intend to release the object, so it should not be expected to become available. 'No entry' means no release state has been assigned. For ABAP Cloud the effect is the same: you cannot use either. The difference is in planning. A not-to-be-released object will not become usable, so you should plan a replacement. A no-entry object might be released later, but you cannot rely on that. In one lab count, about 97% of BAPIs had no entry and about 2.7% were explicitly not to be released.

Senior In a three-level managed RAP BO, child object pages show headers like '8001 / /'. How would you investigate?

I would start with the @UI.headerInfo annotation on the projection view of each affected entity. I would list which fields feed title and description. Then I would check whether those fields are populated for child rows, since an empty value leaves a trailing separator. Next I would check the composition and parent association definitions in the BDEF and the projection views, including redirection to the parent and child projections. I would also look at the facet and line item annotations for the children. If the parent value is needed on the child page, I would expose it as a field through the parent association.
