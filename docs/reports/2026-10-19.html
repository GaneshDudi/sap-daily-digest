Calling an LLM from ABAP Cloud with the ABAP AI SDK

The post describes the ABAP AI SDK as a thin layer over ISLM (Intelligent Scenario Lifecycle Management), which manages lifecycle, connectivity, deployment and prompts. ISLM connects to the Generative AI Hub in SAP AI Core, so no hand-written HTTP or JSON is needed.

Prerequisites come first: subscribe to SAP AI Core, create a service instance and service key, and create a communication arrangement for scenario SAP_COM_0A69 (customer-managed outbound). Then an ISLM scenario, for example Z_MY_SCENARIO, must exist.

The call has three steps: cl_aic_islm_compl_api_factory=>get( )->create_instance( 'Z_MY_SCENARIO' ) returns the API object, execute_for_string( ... ) sends the prompt, and get_completion( ) on the result returns the text. The excerpt does not show full signatures, so check them in ADT.

The Prompt Library API uses ISLM-managed prompt templates with parameters, which moves prompt text out of code. Orchestration through the SAP AI Core Orchestration Service adds data masking and document grounding. The post says the SDK is available in S/4HANA Cloud Private Edition/On-Premise, Public Edition and the ABAP environment; the post's vendor-neutrality claim should be tested in a real system.

Why a published custom field is not exposed in a standard Public Cloud app

The question describes field YY1_ContractEngineer (Text, 12) published on business context MM_PURDOC_HEADER. The mass-change views C_PURCNTRLCONTRMASSUPDT, C_PURCNTRLCONTITMMASSUPDT and C_PURCNTRLCONTRHIERMASSUPDT are enabled, yet the field is not selectable in Mass Changes to Purchase Contracts.

The post suggests that publication and exposure are separate steps. A field must be in the app's relevant CDS views and be offered by the app's own field configuration. The asker lists possible causes: business context fit for central versus local contracts, type or length limits, activation or refresh, and authorisations. No answer is given.

A practical check is to confirm the field appears in the Custom Fields app's User Interfaces tab for the right app, then check whether the mass-change view lists it as an extension element. Treat this as a diagnostic plan, not a confirmed fix.

Senior A user asks for a Fiori Elements report on a screen value for which you find no table. How do you proceed?

I would not assume the value is stored. Many values are computed at runtime and held in structures filled by the application logic, as in the WB2R_SV Net Amount case. I would debug from the UI, find the structure behind the field, and use where-used to locate the method that fills it. Then I decide whether to reuse that logic, reproduce the calculation in a CDS view, or persist results. I would also confirm the calculation depends on context, such as settlement runs, before committing to a report. Only then do I estimate and promise the delivery.
