Troubleshooting ADS PDF output in Fiori: output devices and device types

The reported error is 'Cannot find PDL type for output device LOCL'. LOCL is defined in SPAD as device type G (SAPWIN frontend printing). The thread says the error occurs in Fiori app F2328 and also in SAP GUI via FP_TEST_00. That means the problem does not depend on the Fiori layer. It sits in the Adobe Forms rendering and spool path.

The reported workaround is to use an output device whose type is not F or G. The thread does not explain why. The likely reading is that ADS needs a device type with a usable PDL type, which frontend-printing types do not provide. That is an inference, not something the post confirms.

A practical method: reproduce with FP_TEST_00 using the same output device. Then check which device the user gets by default (SU01 defaults, or user parameters). Then check the device type and its PDL assignment in SPAD. Last, retest with a non-frontend device. This separates configuration from application code.

Verifying NEW-PAGE obsolete spool parameter flags empirically

The NEW-PAGE PRINT ON statement accepts obsolete parameters such as IMMEDIATELY and KEEP IN SPOOL, each given as a one-character field. According to Sandra's tests, a non-blank value such as 'X' activates the flag and a blank deactivates it. The keyword documentation, in both English and German, states the reverse.

The pattern is a one-character flag field, which is standard ABAP. A test is therefore simple: write a small report with PRINT ON, pass 'X' and then space for the flag, and check the resulting spool request attributes in SP01. This shows the actual behavior.

The takeaway for legacy maintenance: do not trust documentation for obsolete statements without a test, and report errors to SAP. Prefer the current parameter structure, such as the one used with GET_PRINT_PARAMETERS, over obsolete inline specifications.

  • NEW-PAGE PRINT ON
  • IMMEDIATELY
  • KEEP IN SPOOL
  • Flag fields ('X' / blank)
  • SP01 spool attributes

Mid-level A Fiori app shows 'Cannot find PDL type for output device' when previewing an ADS PDF. How do you diagnose it?

First isolate the layer. Run FP_TEST_00 in SAP GUI with the same form and output device. If it fails there, the Fiori app is not the cause. Then check which output device the user receives, from SU01 defaults or parameters. Then open the device in SPAD and check its type. In the reported case, LOCL was type G (SAPWIN frontend printing), and the reported workaround was a device type other than F or G. Retest with such a device. Finally, confirm that ADS itself is reachable and working. I would treat the explanation that frontend types lack a usable PDL type as a hypothesis, not a confirmed fact.
