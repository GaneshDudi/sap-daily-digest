Validating DDL on HANA decimal columns

The XLC post describes an ALTER TABLE on a DECIMAL column that completes with no error and an unchanged row count, yet a stored value changes from 219 to 0.000219 [86]. The author varied precision, scale and compression to find when values change. Only the introduction is available, so the conditions are not confirmed here. Read SAP Note 3849542 for the affected releases and the fix.

The practical lesson is about what counts as proof. A row count only shows that rows survived. For numeric columns, take an aggregate snapshot before the change, such as COUNT(*), SUM(col), MIN(col) and MAX(col), and compare it afterwards. For critical tables, a checksum over the key and the value columns is stronger.

For ABAP teams the exposure is in table changes made through DDIC activation and conversions, and in direct DDL on custom tables. Test a copy of the table first. The post also costs a workaround on 100 million rows, so plan the downtime and the verification time together.

  • ALTER TABLE on DECIMAL
  • Precision and scale
  • Before/after aggregates
  • SAP Note 3849542
  • Row count is not proof

Debugging a generic OData gateway error on the purchase contract API

The post shows a deep insert into A_PurchaseContract (API_PURCHASECONTRACT_PROCESS_SRV v0002) that works, including nested to_PurContrItemCndnValdty and to_PurContrItmCndnAmount. A later POST to A_PurchaseContract('4600000066')/to_PurchaseContractItem for item 20 fails with /IWBEP/CM_MGW_RT/188 'Service provider did not return any business data' [97].

That message is generic. Take the transaction ID and timestamp from the response and look in /IWFND/ERROR_LOG on the hub, then the backend error log, for the real business message. The post cuts off before this.

Three things in the post are worth checking. First, item 20 was already in the creation payload, so confirm whether it exists on the contract, because a duplicate item number is a plausible cause. Second, the failing payload has FRA1 and RA00 but no PB00, which the working one included. Third, RA00 has ConditionCurrency '%', which should be compared to the condition type configuration. None of these is confirmed in the post.

The general method is to compare the working and failing requests field by field, check $metadata for what the navigation supports, and retest with the smallest payload.

  • /IWFND/ERROR_LOG
  • /IWBEP/CM_MGW_RT/188
  • Condition types PB00, FRA1, RA00
  • $metadata

Filter-first vs filter-after in HANA vector search

The post compares two query shapes for a vector search over SAP guidance content. In the first, a global Top-K is taken by cosine similarity and metadata filters (edition, release) are applied afterwards. In the second, the filter is applied first and ranking happens within the eligible set [17].

The first shape can return fewer results than K, or none, because the best global matches belong to other releases. High scores do not mean the match applies to the user's system. The second shape returns the best matches among applicable content.

The author places applicability mapping and authorization in the CAP search service, so access control is part of the query and not an afterthought. A follow-up with the endpoint and tests is announced. The exact SQL is not in the excerpt, so reproduce it yourself on a HANA Cloud trial.

The ABAP parallel is a familiar one: a WHERE clause that restricts the data before a ranking or UP TO n ROWS is not the same as limiting after the fact.

Interview questions

Grounded in today's material. Open each one to see a model answer.

Senior An ALTER TABLE on a HANA decimal column succeeds and the row count is the same. How do you confirm that no data was altered?

A row count only shows that rows exist, not that values are intact. A recent XLC investigation of SAP Note 3849542 reports a value changing from 219 to 0.000219 with no error. I would take a snapshot before the change: COUNT, SUM, MIN and MAX on the numeric columns, grouped by a sensible key. For critical tables I would add a checksum over key and value columns. After the change I compare the same figures and sample rows. I would run this on a copy first, check the SAP Note for affected releases, and plan time for a workaround on large tables.

Senior A deep insert into an OData V2 API works, but a later POST to a child navigation fails with /IWBEP/CM_MGW_RT/188. How do you analyse it?

The message is generic and does not carry the business reason. I take the transaction ID and timestamp from the response and look in /IWFND/ERROR_LOG on the hub, then the backend log, for the real message. Then I compare the working and failing payloads field by field. In the purchase contract case, item 20 may already exist from the deep insert, and the failing payload has no PB00 condition. I would also check $metadata for what the navigation supports, and retry with the smallest valid payload. The create path and the add-item path should be tested separately.

Architect A team wants to replace an unreleased function module in a custom Fiori/RAP report. How do you approach it under clean core?

First I confirm the release state of the object in ADT, through its API state. Then I look for a released CDS view or released API that covers the data, using the released object catalogue. If none exists, I consider a custom CDS view on released sources, or document a justified exception with a fallback and an owner. I avoid moving the call to BTP and treating that as a fix, because it carries the same unreleased dependency. The decision and its reasoning should be recorded so that upgrades can be checked against it.
