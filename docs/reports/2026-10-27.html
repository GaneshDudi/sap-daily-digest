Deep dives

The most valuable technical posts, explained.

Safe item-level changes to outbound deliveries with BAPIs

The case in ref 35: BAPI_OUTB_DELIVERY_CREATE_SLS with FIFO batch determination produces a parent item with LFIMG 0 and child items (9000xx) carrying the batch. Changing BATCH on the child via BAPI_OUTB_DELIVERY_CHANGE raises VLBAPI 004, a quantity consistency check. Deleting the child and adding a new one with HIERARITEM and USEHIERITM raises /SPE/DIRDLV 006 without STGE_LOC, and 014 when STGE_LOC is passed, because the storage location has no warehouse number.

The main hazard is transactional. One attempt committed the delete before the add failed, leaving a parent without a child. A BAPI that returns errors in RETURN must never be followed by BAPI_TRANSACTION_COMMIT. Check RETURN for types E and A after every call, and call BAPI_TRANSACTION_ROLLBACK on failure. Do the delete and the add in a single call where the BAPI allows it, so there is one LUW.

WS_DELIVERY_UPDATE_2 with VBPOK_TAB and VBKOK_WA was mentioned but not tested. It may behave differently, so test it in a sandbox. A cleaner design may be to influence batch determination at creation time. Whether the BAPI accepts a batch at creation to skip FIFO is an open question in the post, so verify it in your system rather than assume.

From classic table to released CDS view

Ref 42 describes a report that starts from a table or field and proposes CDS objects. The excerpt shows no code, so the matching logic is not known. The approach is a direct field relationship, found by looking at which CDS views expose a given table field.

In ADT, you can do something similar by hand. Open the released object tree for the API state, search for CDS views whose data source is the table, and check the release contract (C1 for use in key user and ABAP Cloud, or C0 for extension). The post also lists the Cloudification Repository, which gives successor objects for released/classic objects, and SAP Business Accelerator Hub.

A field match does not mean the CDS view is a semantic replacement. Filters, joins, currency or unit conversion and authorization checks in the view can change the result. Compare row counts and values against the table for a sample before replacing a SELECT in custom code.

Managed RAP: validations, determinations, actions and draft

Ref 52 is a learner series on managed RAP for S/4HANA 2023. The excerpt lists the features but shows no code, so what follows is general RAP background and not from the post.

In the behavior definition, a validation is declared with the trigger operations and fields, for example validation validateX on save { create; field Y; }, and a determination with determination setDefaults on modify { create; }. Custom actions are declared with action and implemented in the handler class with a MODIFY ENTITIES statement. Draft needs a draft table and the with draft statement, plus the draft actions Edit, Activate, Discard and Resume.

Common problems for learners are validations that fire on the wrong trigger, missing failed and reported entries so messages do not reach the UI, and a missing draft table. A useful teaching step is to have students write each handler method themselves and watch the Fiori Elements behaviour.

Interview questions

Grounded in today's material. Open each one to see a model answer.

Senior A BAPI_OUTB_DELIVERY_CHANGE call that swaps a batch-split child item fails after you already deleted the old child. How do you keep the delivery consistent?

Evaluate the RETURN table after every BAPI call and treat types E and A as failure. On failure call BAPI_TRANSACTION_ROLLBACK and never BAPI_TRANSACTION_COMMIT, so the delete is not persisted. Better, put delete and add in one BAPI call so they share one update, rather than committing between them. Check that the BAPI does not commit internally in your release. In the case reported, a delete was committed before the add failed, leaving a parent with no child. Also consider whether batch can be set at creation, or whether another interface such as WS_DELIVERY_UPDATE_2 is supported. Test any alternative in a sandbox, not production.

Senior You must find the released CDS view that replaces direct reads of a classic table, with no successor listed. How do you proceed?

First check the Cloudification Repository for a successor, then the released object tree in ADT and the Business Accelerator Hub. Search CDS views whose data source is the table and which expose the needed fields. Check the release contract (C1 or C0) so the view is allowed in ABAP Cloud or extension use. A field-level match is not proof of equivalence, because the view may add filters, joins, conversions or authorization checks. Compare row counts and values on sample data against the old SELECT. Document the result, and use a mapper report only as a starting point.

Architect An agent generates ABAP tools that are exposed to an LLM through an MCP server. What would you review before transporting them?

Check authorization first: each tool should run with the caller's authorizations and use explicit AUTHORITY-CHECK statements, not a technical user with broad rights. Check that write paths do not commit unexpectedly and that commit and rollback are controlled by one owner. Review error handling, so failures return clear messages and do not leave partial updates. Check input validation, because LLM-supplied parameters are untrusted. Run ATC with the clean-core checks and require normal code review and unit tests. Limit the tool list to the read access that is needed, and log tool calls for audit. The post gives none of these details, so this is a review standard, not a description of that project.

Class idea

Safe delivery changes with BAPIs: return handling, LUWs and batch split

Today's most technical question (ref 35) shows a BAPI path failing where VL02N works, plus a delete committed before the add failed. A related status BAPI question (ref 36) shows rules that BAPIs enforce.

  1. Delivery item hierarchy: parent, child, HIERARITEM, USEHIERITM
  2. How batch determination creates 9000xx items
  3. Reading RETURN: types, message classes VLBAPI and /SPE/DIRDLV
  4. Commit and rollback rules, and one LUW for delete plus add
  5. Why status BAPIs refuse some changes (CNIF_STATUS001)
  6. Alternatives: WS_DELIVERY_UPDATE_2, steering batch at creation
  7. Writing a wrapper class that rolls back on any E or A message

Hands-on exercise: In a sandbox, create a delivery for a batch-managed material with FIFO determination. Write an ABAP class that calls BAPI_OUTB_DELIVERY_CHANGE to set a different batch on the child item.
