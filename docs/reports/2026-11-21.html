Keyword Doc omits CX_SY_DYN_CALL_ILLEGAL_METHOD for static interface method calls

A developer reports that the Static Method Calls documentation lists CX_SY_NO_HANDLER and CX_SY_REF_IS_INITIAL but not CX_SY_DYN_CALL_ILLEGAL_METHOD. That exception, with runtime error CALL_METHOD_NOT_IMPLEMENTED, occurs when a class declares an interface but does not implement a called method. The repro is a global class with INTERFACES if_abap_api_state that calls if_abap_api_state~is_released( ) in if_oo_adt_classrun~main. The issue has been filed with the documentation team, with no reply yet.

Why it matters: It is a catchable exception that the docs do not mention, and the repro is small enough to run in minutes. Good material for showing how to check behaviour instead of relying on documentation.

Unimplemented interface methods: CX_SY_DYN_CALL_ILLEGAL_METHOD

The reported case: a global class declares INTERFACES if_abap_api_state but does not implement is_released. A static call to if_abap_api_state~is_released( ) from if_oo_adt_classrun~main ends in runtime error CALL_METHOD_NOT_IMPLEMENTED, with the exception CX_SY_DYN_CALL_ILLEGAL_METHOD. The author says the Static Method Calls documentation lists CX_SY_NO_HANDLER and CX_SY_REF_IS_INITIAL but not this one, and has filed it with the documentation team.

The practical lesson is to reproduce it. Create the class in ADT, run it with F9, and look at the short dump. Then wrap the call in TRY ... CATCH cx_sy_dyn_call_illegal_method and check whether the handler fires in your release. The post gives no release, so do not assume the behaviour is identical across systems.

It also shows that an interface does not have to be fully implemented for the class to activate in this scenario, which is why the failure only appears at runtime. Tell students not to rely on the documentation's exception list as complete, and to test unusual paths.

Moving from ADT-deployed Fiori apps to BAS

Apps deployed from ADT or the Fiori generator live in the SAPUI5 ABAP Repository. In BAS, Import Project and Open Folder only reach the local workspace, so the app does not appear. The post's answer is the command palette entry 'Fiori: Download ADT Deployed App from SAPUI5 ABAP Repository'.

The flow: select a BTP destination (BAS uses its stored credentials), select the app by title, ID or package, then choose a target folder. The result should contain webapp/, manifest.json, ui5.yaml, ui5-local.yaml, ui5-mock.yaml, ui5-deploy.yaml, .appGenInfo.json and archive.zip.

If the command is missing, install the Fiori extensions and restart; if the destination is missing, check it in the BTP cockpit. The post does not cover ABAP-side authorizations or repository details, so add those yourself when teaching.
